
# Security configuration

## API có thể bị tấn công nếu

- Thiếu biện pháp tăng cường bảo mật phù hợp ở bất kỳ phần nào của application stack hoặc nếu có quyền được cấu hình không đúng cách.
- Các bản vá bảo mật mới nhất bị thiếu hoặc hệ thống đã lỗi thời.
- Các tính năng không cần thiết được bật (ví dụ: HTTP)
- Giao thức bảo mật truyền tải (TLS) bị thiếu.
- Chỉ thị bảo mật không được gử từ máy khách.
- Chính sách CORS bị thiếu hoặc khôgn được thiết lập đúng cách.
- Error messages include stack traces, or other sensitive information is exposed.


## Yêu cầu

Vòng đời của API phải bao gồm:
- Một quá trình hardening có thể lặp lại giúp triển khai nhanh chóng và dễ dàng một môi trường được khoá chặt đúng cách.
- Nhiệm vụ xem xét và cập nhật cấu hình trên tàon hộ ngăn xếp API. Đánh giá phải bao gồm: orchestration files, API components, and cloud services (e.g., S3 bucket permissions).
- Một kênh truyền thông an toàn cho tất cả các tương tác API truy cập vào các tài nguyên tĩnh (ví dụ hình ảnh).
- Một quy trình tự động để liên tục đánh giá hiệu quả của cấu hình và cài đặt trong mọi môi trường.

Hơn nữa:
- Để ngăn chặn ngoại lệ và các thông tin có giá trị khác được gửi lại cho kẻ tấn công, nếu có thể, hãy xác định và thực thi tất cả các API response payload schemas including error responses.
- Đảm bảo API chỉ có thể được truy cập bởi HTTP verbs được chỉ định. Tất cả các HTTP verbs khác phải bị vô hiệu hoá (ví dụ: `HEAD`)
- Các API phải được triển khai chính sách CORS phù hợp.
