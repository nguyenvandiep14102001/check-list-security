# Resources & Rate Limiting

## API dễ bị tấn công nếu

API requests tiêu tốn tài nguyên như mangk, CPU, bộ nhứo và lưu trữ. Lượng tài nguyên cần thiết để đáp ứng yêu cầu phụ thuộc rất nhiều vào đầu vào của người dùng và endpoint business logic. Ngoài ra, hãy xem xét thực tế là các yêu cầu từ nhiều máy khách API cạnh tranh để giành tài nguyên. API dễ bị tấn công nếu thiết ít nhất một trong các giới hạn sau hoặc được đặt không phù hợp (ví dụ: quá cao/quá thấp):
- Execution timeouts
- Max allocable memory
- Number of file descriptors
- Number of processes
- Request payload size (e.g., uploads)
- Number of requests per client/resource
- Number of records per page to return in a single request response

## Yêu cầu

- Áp dụng giới hạn về tần suất khách hàng có thể gọi API trong một khung thời gian xác định.
- THông báo cho khách hàng khi vượt quá giới hạn bằng cách cung cấp số hạn mức và thời gian hạn mức sẽ được thiết lập lại.
- Thêm xác thực phía máy chủ phù hợp cho query string and request body parameters, đặc biết là tham số kiểm soát số lượng bản ghi được trả về trong phản hồi.
- Xác định và áp dụng maximum size trên tất cả các tham số và dữ liệu đầu vào như độ dài tối đa cho chuỗi và số lượng phần từ tối da trong mảng.
- Đối với các phương thức API request, cần có những biện pháp phù hợp với thời gian xử lý. Ví dụ như cần có cơ chế cache data cho GET request để giảm thiểu thời gian xử lý đối với những request giống nhau. Hoặc thêm các xác thực đối với các PUT request (chẳng hạn dùng eTag) để xác định version dữ liệu, từ đó chặn các request có data bất thường.
